# Codebase Review & Refactor — Findings

Scope: whole monorepo (`apps/api`, `apps/web`). Each finding lists severity, impact and the fix.
Severity: 🔴 bug/security · 🟠 correctness/robustness · 🟡 architecture/maintainability · 🔵 UX.

## Backend (NestJS)

| #   | Sev | Finding                                                                                                                                                                      | Fix                                                                                                                                   |
| --- | --- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 🔴  | **Scoring race:** an answer saved while an attempt was being finalized could change `selectedOptionId` after scoring, so the totals and per-question `isCorrect` disagreed.  | Answer writes and finalization run in transactions that lock the attempt row (`SELECT … FOR UPDATE`).                                 |
| 2   | 🔴  | **Shared rate limit:** server-rendered pages called the API without the visitor's IP, so every SSR visitor shared one 120 req/min bucket and the site could throttle itself. | `serverApi` forwards `X-Forwarded-For`; trusted proxy hops are configurable via `TRUST_PROXY_HOPS`.                                   |
| 3   | 🔴  | **Sessions survived a password change** for up to 7 days.                                                                                                                    | `User.sessionVersion` is embedded in the JWT and checked by the guard; it increments on password change and on deactivation.          |
| 4   | 🟠  | **Login timing leak:** unknown emails skipped bcrypt, which made account enumeration possible.                                                                               | Always compare against a dummy hash (`verifyPassword`).                                                                               |
| 5   | 🟠  | **Double-click on "Start exam"** hit the unique constraint and returned a raw 409.                                                                                           | P2002 is caught and the in-progress attempt is resumed.                                                                               |
| 6   | 🟠  | **Submit failed** if time expired between the request arriving and the answer flush.                                                                                         | Late flushes on submit are dropped; the attempt is still scored.                                                                      |
| 7   | 🟠  | **Premium leak:** a question could be switched to PREMIUM while used in a FREE exam.                                                                                         | Blocked with a clear 400.                                                                                                             |
| 8   | 🟠  | **Orphaned files:** deleting a subject left its uploaded note files on disk.                                                                                                 | Files are collected and removed after the delete.                                                                                     |
| 9   | 🟠  | **Topic counts disagreed** between the subject list, the subject page and progress when a parent topic was unpublished; hidden subtopics could still be marked complete.     | One `flattenTopicTree`/`buildTopicTree` utility is used everywhere; `markComplete` requires a visible parent.                         |
| 10  | 🟠  | **Writes on reads:** `GET /exams/today` did an `upsert` (a database write) on every request.                                                                                 | Read first; create only when the row is missing.                                                                                      |
| 11  | 🟠  | **Wrong status code:** "Current password is incorrect" returned 401, which clients treat as an expired session.                                                              | Returns 400 instead.                                                                                                                  |
| 12  | 🟡  | **Swagger was always public.**                                                                                                                                               | Off in production unless `ENABLE_SWAGGER=true`.                                                                                       |
| 13  | 🟡  | **Duplication:** string transformers were redefined in 10 DTOs; slug and `DAY_MS` logic were duplicated; a constant was imported from another service.                       | Shared `common/dto/transforms`, `findAvailableSlug`, `common/utils/time` and `exam.constants`.                                        |
| 14  | 🟡  | **Credential logic split:** password logic was spread across the users and auth modules.                                                                                     | Auth owns credentials (`auth/password.ts`; `POST /auth/password` reissues the cookie).                                                |
| 15  | 🟡  | **Bootstrap drift risk:** the HTTP pipeline was defined only in `main.ts`.                                                                                                   | `configureApp()` is shared by `main.ts` and the e2e tests.                                                                            |
| 16  | 🟡  | **No integration tests.**                                                                                                                                                    | Supertest e2e suite on an isolated schema: auth, RBAC, session revocation, premium gating, the full exam lifecycle, races and expiry. |

## Frontend (Next.js)

| #   | Sev | Finding                                                                                                                             | Fix                                                                                                                            |
| --- | --- | ----------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------ |
| 17  | 🔴  | **Auto-submit loop:** a failed auto-submit at 00:00 re-fired on every render and hammered the server.                               | Fires exactly once; a failure shows **Retry submit** and **View result** (the server also finalizes on read).                  |
| 18  | 🔴  | **Out-of-order saves:** rapid answer changes were sent in parallel and could be stored in the wrong order.                          | Saves are serialized per attempt (TanStack mutation `scope`); unsynced answers are tracked per question and flushed on submit. |
| 19  | 🔴  | **Session helper swallowed Next.js control-flow errors** (dynamic-rendering bailout), which could pre-render pages as "signed out". | `unstable_rethrow` in `getSessionUser` and the sitemap.                                                                        |
| 20  | 🟠  | **Expired sessions** showed a generic error on every widget.                                                                        | A global 401 handler in the Query/Mutation caches shows one toast and redirects to `/login?next=…`.                            |
| 21  | 🟠  | **Login ignored `?next=`** for users who were already signed in.                                                                    | Honoured, via `safeRedirect`.                                                                                                  |
| 22  | 🟡  | **Exam runner mixed logic and UI** (~150 lines).                                                                                    | `useExamSession` (state and effects), `useExamShortcuts` and an `ExamStatusBar` component.                                     |
| 23  | 🟡  | **Seven admin tables duplicated** search, debounce, filter and pagination logic plus their loading, error and empty states.         | `useListQuery` hook, `DataTableCard`, `EditLinkButton`; each row is its own component.                                         |
| 24  | 🔵  | **No feedback** while a server-rendered page loaded.                                                                                | `loading.tsx` skeletons for each route group.                                                                                  |
| 25  | 🔵  | **Exam usability.**                                                                                                                 | Keyboard shortcuts (A–D / 1–4, ←/→) and warnings at 5 minutes and 1 minute.                                                    |
| 26  | 🔵  | **Dead end after results.**                                                                                                         | A "Next steps" card: weak topics, retake (if allowed), dashboard.                                                              |
| 27  | 🔵  | **Weak topics weren't actionable.**                                                                                                 | Each one has a **Revise** link to its topic page.                                                                              |
| 28  | 🔵  | **Long topics were hard to navigate.**                                                                                              | An "On this page" table of contents when a topic has several notes.                                                            |
| 29  | 🔵  | **Accessibility.**                                                                                                                  | Skip-to-content link; focusable `main` landmark; live progress text in the exam.                                               |
| 30  | 🔵  | **SEO.**                                                                                                                            | `robots.txt` (private areas disallowed) and a `sitemap.xml` of subjects and running circulars.                                 |

## Known limitations (not changed, documented)

- **Premium attachments:** files are served by unguessable URL; they are not authorization-checked per request. An authenticated download endpoint is the next step.
- **Shared types:** the web API types are hand-written; generating them from Swagger (`openapi-typescript`) would prevent drift.
- **No refresh tokens:** sessions are 7-day JWTs, which is acceptable for web. The mobile app will need refresh tokens.
